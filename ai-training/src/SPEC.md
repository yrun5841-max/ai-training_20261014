# シャッフルランチ 仕様書（ドラフト）

> ステータス: 仕様の掘り下げ中。「9. 未決事項」を決めてから実装に入ります。

## 1. 背景・目的

- 社内にコミュニケーションの場を設けたい。
- 日頃あまり会話しない人、年の離れた人、他部署の人と交流するきっかけをつくる。
- 特に、新入社員や他部署から異動してきた方が社内に知り合いを増やせるようにする。
- **簡単に申し込めること**を最も重視する。

## 2. 利用者と役割

| 役割 | 説明 |
| --- | --- |
| 参加者（新入社員） | 主な対象。トップ画面のフォームから申し込み、結果の公開後に自分のグループを同じ画面で確認する。 |
| 参加者（異動者） | 主な対象。他部署から異動してきた方。操作は新入社員と同じ。 |
| 参加者（既存社員） | 交流相手として参加する。社内に詳しい人として、各グループに1人以上入る。 |
| 管理者（幹事） | 申込者の確認、シャッフルの実行、結果の確認と公開を行う。 |

## 3. 開催の流れ

月1回開催します。

1. 開催日・締め切り日は自動で決まる（6章を参照）
2. 参加者がトップ画面のフォームから申し込む
3. 締め切り日を過ぎると、自動で受付を終了する
4. 管理者がシャッフル（グループ分け）を実行する
5. 管理者が結果を確認する。気に入らなければ再実行する
6. 管理者が結果を公開する
7. 参加者がトップ画面で自分のグループを確認する
8. 各グループでランチに行く

## 4. 機能要件

### 4.1 申し込み（参加者）

- 入力する項目（4項目のみ）
  - 名前（必須）
  - 部署（必須。一覧から選ぶ）
  - 入社年（必須。初期値は今年）
  - 区分（必須。ボタンで選ぶ）: 新入社員／異動者／既存社員
- 受け付けない入力
  - 名前が空、または空白だけ（前後の空白は取り除く）。31文字以上
  - 部署が一覧にない
  - 入社年が1970年より前、または来年以降
  - 区分が上の3つ以外
- 年代は入力しない。年次のばらつきは入社年だけで判断する
- 申し込み時に識別用のコードを発行し、ブラウザの Cookie に保存する
- 締め切り前なら、申し込みを取り消せる（申し込んだ端末・ブラウザからのみ）
- ログインはしない

### 4.2 シャッフル（管理者）

- 締め切り後に、ボタンでグループ分けを実行する
- 結果を公開する前なら、何度でも再実行できる
- 条件を満たせなかったグループがある場合は、画面で警告する（5章を参照）

### 4.3 結果の公開・閲覧

- 管理者が「公開」するまで、参加者には結果を見せない
- 公開後、参加者はトップ画面で**自分のグループだけ**を確認できる（メンバーの名前・部署）
- 本人の判定には Cookie の識別コードを使う。申し込みとは別の端末・ブラウザでは結果を見られない（制約として許容する）
- 結果確認用の画面は設けない
- 結果は開催日の当日まで表示する。翌日からトップ画面は翌月の募集に切り替わる

## 5. グループ分けのルール

### 5.1 人数

- 1グループは **3〜4人**
- 2人のグループは作らない（2人でランチに行くのはハードルが高いため）
- 基本は3人ずつに分け、余った人は4人のグループに入れる
  - 例: 10人 → 3人 × 2 ＋ 4人 × 1
  - 例: 11人 → 3人 × 1 ＋ 4人 × 2
- 申込者が3人未満のときは開催しない
- 申込者が5人のときは3〜4人に分けられないため、例外として **5人で1グループ** にする

### 5.2 条件と優先順位

上から順に優先します。

1. **必須**: 1グループ3〜4人（5人のときだけ5人）
2. **できるだけ守る**: 同じグループに同じ部署の人を入れない
3. **できるだけ守る**: 各グループに既存社員を1人以上入れる
4. **できるだけ守る**: 入社年がばらけるようにする（全員が同じ入社年のグループを作らない）

「できるだけ守る」条件は、**守れる組み合わせが1つでもあれば必ず守る**。何度実行しても同じように守られること（偶然に頼らない）。
条件どうしがぶつかって両方は守れないときは、上の条件を優先する。

### 5.3 条件を満たせないとき

- 2〜4の条件を満たせないグループがあっても、グループ分けはする
- どの条件を満たせなかったかを管理者の画面に表示し、再実行するか判断してもらう
  - 例: 既存社員の申込者がグループ数より少ない、部署の偏りが大きい
- 警告を出す条件
  - 同じ部署の人がいる（部署名を表示）
  - 既存社員がいない
  - 全員の入社年が同じ

## 6. 開催日・締め切り日

- 開催日: 毎月**第3金曜**（全グループ同じ日）
- 締め切り日: 開催日の**1週間前**。締め切り日の **23:59（日本時間）** まで受け付ける
- 日付はすべて日本時間で判定する
- 募集設定の画面は設けない。祝日などで日付を変えたい月は、コード内の設定ファイル（例: `lib/schedule.ts`）で上書きする

## 7. 画面

### 7.1 画面一覧

| 画面 | 利用者 | 内容 |
| --- | --- | --- |
| トップ | 参加者 | 見出し、開催日・締め切り日、申し込みフォーム、取り消し、自分のグループ（公開後） |
| 管理: 申込者一覧 | 管理者 | 申込者の一覧（区分・部署別の人数） |
| 管理: シャッフル | 管理者 | 実行・再実行、警告の表示、公開 |

### 7.2 トップ画面の表示

参加者が使う画面はトップだけで、スクロールせずに1画面に収める。時期によって表示を切り替える。

| 時期 | 表示 |
| --- | --- |
| 受付中（未申し込み） | 見出し＋開催日・締め切り日（1行）＋申し込みフォーム |
| 受付中（申し込み済み） | 「申し込みました！」＋取り消しボタン |
| 締め切り後〜公開前 | 「グループ分けの結果をお待ちください」 |
| 公開後 | 「あなたのグループ」としてメンバー（名前・部署）を表示 |
| 公開後（申し込みなし） | 「今月の受付は終了しました」 |

### 7.3 デザイン

- 見出し: **「ランチで、はじめまして。」**（短く大きく表示し、添え字として `SHUFFLE LUNCH`）。説明文は置かないか1行まで
- 配色（2色）
  - 主色: オレンジ `#F97316`（見出し、「あなたのグループ」の枠など）
  - アクセント色: ティール `#0D9488`（送信ボタン、選択中の区分ボタンなど）
  - `app/globals.css` の `@theme inline` に `--color-primary` / `--color-accent` として定義する。ダークモード用に明るめの色を用意する

- 参加できない日の調整
- 募集設定の画面
